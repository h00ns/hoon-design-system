# Dialog

페이지 위에 떠서 **지금 하던 일을 잠시 멈추고 집중해야 하는 작업**을 보여주는 모달 창.
짧은 입력 폼, 세부 정보 확인, 설정 변경처럼 현재 맥락을 유지한 채 끝낼 수 있는 일에 쓴다.
되돌릴 수 없는 동작을 확인받는다면 [AlertDialog](?path=/docs/components-alertdialog--docs) 를,
페이지를 가리지 않는 가벼운 패널이라면 [Popover](?path=/docs/components-popover--docs) 를 쓴다.

## 사용법

```tsx
import { Button, Dialog } from '@hoon-ds/react';

<Dialog.Root>
  <Dialog.Trigger asChild>
    <Button>프로필 편집</Button>
  </Dialog.Trigger>
  <Dialog.Content>
    <Dialog.Header>
      <Dialog.Title>프로필 편집</Dialog.Title>
      <Dialog.Description>변경한 내용은 저장을 눌러야 반영됩니다.</Dialog.Description>
    </Dialog.Header>
    <Dialog.Body>{/* 내용 */}</Dialog.Body>
    <Dialog.Footer>
      <Dialog.Close asChild>
        <Button variant="secondary">취소</Button>
      </Dialog.Close>
      <Button onClick={save}>저장</Button>
    </Dialog.Footer>
  </Dialog.Content>
</Dialog.Root>;
```

| 부품          | 역할                                                                  |
| ------------- | --------------------------------------------------------------------- |
| `Root`        | 열림 상태. `open`/`onOpenChange`(제어) 또는 `defaultOpen`(비제어)     |
| `Trigger`     | 여는 요소. `asChild` 로 Button 을 감싼다                              |
| `Content`     | 포털 · 오버레이 · 포커스 트랩 · 스크롤 잠금 · 닫기 버튼을 포함한 본체 |
| `Header`      | 제목과 설명 영역 (고정)                                               |
| `Title`       | **필수.** 다이얼로그의 접근 가능한 이름                               |
| `Description` | 접근 가능한 설명. 없으면 `Content` 에 `aria-describedby={undefined}`  |
| `Body`        | 스크롤 영역. 내용이 넘쳐도 Header · Footer 는 제자리에 있다           |
| `Footer`      | 동작 버튼 영역 (고정)                                                 |
| `Close`       | 닫는 요소. `asChild` 로 Button 을 감싼다                              |

## 예시

### 크기

`sm` 384px · `md` 512px · `lg` 768px · `full` 화면 전체. **640px 미만 화면**에서는 모든 크기가 엄지로 닿기 쉬운 하단 시트로 바뀌고,
`full` 은 노치·홈 인디케이터 영역(safe area)을 피해 전체 화면을 채운다. Footer 버튼도 세로로 쌓이며 주요 버튼이 위로 온다.

<Canvas of={DialogStories.Sizes} />

### 긴 내용

다이얼로그 높이는 화면을 넘지 않는다. 내용이 넘치면 **페이지가 아니라 Body 만 스크롤**되고, 이때 Body 는 자동으로 포커스 가능해져
키보드 사용자도 방향키로 스크롤할 수 있다.

<Canvas of={DialogStories.LongContent} />

### 설명 없음

설명이 필요 없는 다이얼로그는 `Content` 에 `aria-describedby={undefined}` 를 넘긴다. 이렇게 명시하면 Radix 의 경고 없이 설명 연결이 생략된다.

<Canvas of={DialogStories.WithoutDescription} />

### 보이지 않는 제목

디자인상 제목을 보여주지 않더라도 스크린리더용 이름은 있어야 한다. `VisuallyHidden` 으로 `Dialog.Title` 을 감싼다.

<Canvas of={DialogStories.HiddenTitle} />

### 제어 모드와 폼

저장이 끝난 뒤 닫으려면 `open` / `onOpenChange` 로 직접 제어한다. `<form>` 으로 감싸면 Enter 로 제출할 수 있다.
저장 전 닫기를 막고 싶다면 `onOpenChange(false)` 를 무시하거나 AlertDialog 로 한 번 더 확인한다.

## 접근성

[WAI-ARIA APG Dialog (Modal) 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)을 따른다.

### 키보드

| 키                | 동작                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| `Enter` / `Space` | 트리거에서 다이얼로그를 연다                                           |
| `Tab`             | 다이얼로그 안의 다음 요소로 이동. 마지막 요소에서는 첫 요소로 돌아간다 |
| `Shift + Tab`     | 이전 요소로 이동. 첫 요소에서는 마지막 요소로 간다                     |
| `Esc`             | 다이얼로그를 닫고 트리거로 포커스를 돌려준다                           |

### 스크린리더

- `role="dialog"` + `aria-modal="true"`. `Title` 이 `aria-labelledby`, `Description` 이 `aria-describedby` 로 자동 연결된다.
- 열려 있는 동안 바깥 콘텐츠는 `aria-hidden` 처리되어 가상 커서가 다이얼로그를 벗어나지 않는다.
- 열리면 포커스가 다이얼로그 안 **첫 번째 포커스 가능한 요소**로 이동한다. 닫기(X) 버튼은 화면상 우측 상단에 있지만 DOM 에서는 마지막에 있어,
  첫 포커스가 닫기 버튼이 아니라 실제 내용으로 간다. 다른 요소에 먼저 포커스를 주려면 `onOpenAutoFocus` 에서 지정한다.
- 닫기 버튼의 이름은 기본 `"닫기"`. 다국어 서비스라면 `closeLabel` 로 바꾼다.
- 닫히면 포커스가 다이얼로그를 연 트리거로 돌아간다.

### 사용자 설정

- `prefers-reduced-motion` 이면 확대·슬라이드 없이 짧은 페이드만 남는다.
- Windows 고대비 모드에서 그림자 대신 시스템 색 테두리로 경계가 보인다.
- 열려 있는 동안 페이지 스크롤이 잠기고, Body 끝에서 스크롤이 페이지로 이어지지 않는다 (`overscroll-behavior: contain`).
- 브라우저를 200% 확대해도 다이얼로그 높이가 화면을 넘지 않고 Body 가 스크롤된다.
