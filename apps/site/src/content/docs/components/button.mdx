사용자가 **동작을 실행**하게 하는 버튼. 저장, 제출, 열기, 삭제처럼 현재 화면에서 무언가를 일으킬 때 쓴다.
다른 페이지로 **이동**한다면 링크(`<a>`)가 맞고, 버튼처럼 보여야 할 때만 `asChild` 로 감싼다.

<Preview code={basicCode}>
  <Basic client:idle />
</Preview>

## 사용법

```tsx
import { Button } from '@hoon-ds/react';
```

### 크기

`sm` 32px · `md` 40px · `lg` 48px. 모든 크기가 최소 터치 타깃(24px)을 넘는다. 높이는 `min-height` 라 글자를 키워도 잘리지 않는다.

기본 `disabled` 는 포커스를 받지 않는다. 비활성 **이유**를 알려줘야 하면 `focusableWhenDisabled` 로 포커스를 유지하고 Tooltip 이나 설명을 연결한다.

## 접근성

### 키보드

| 키                | 동작                 |
| ----------------- | -------------------- |
| `Tab`             | 버튼으로 포커스 이동 |
| `Enter` / `Space` | 실행                 |

### 스크린리더

- 네이티브 `<button>` 이라 역할과 상태를 브라우저가 그대로 전달한다.
- 기본 `type="button"`: 폼 안에 두어도 의도치 않게 제출되지 않는다. 제출 버튼은 `type="submit"` 을 명시한다.
- `loading` 은 `aria-busy="true"` + `aria-disabled="true"`. 작업 **결과**(성공/실패)는 [Toast](/components/toast/) 나 live region 으로 따로 알린다.
- `asChild` 로 링크를 렌더링하면 비활성은 `aria-disabled` 로 표현하고 이동을 막는다.

### 사용자 설정

- Windows 고대비 모드에서 테두리와 포커스 링이 시스템 색으로 보인다.
- `prefers-reduced-motion` 이면 로딩 스피너가 느리게 돈다 (진행 중이라는 의미는 유지).
- 터치 기기에서는 hover 스타일이 눌린 채 남지 않는다.
