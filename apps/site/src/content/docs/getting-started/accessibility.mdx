이 디자인 시스템의 목표는 **WCAG 2.2 AA** 다. 컴포넌트가 기본값으로 많은 것을 보장하지만, **모든 것을 보장하지는 못한다.** 아래는 컴포넌트가 해주는 것과 사용하는 쪽에서 챙겨야 하는 것이다.

## 컴포넌트가 보장하는 것

- **키보드** — 모든 컴포넌트를 키보드로 조작할 수 있고, 동작은 [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/) 패턴을 따른다.
- **포커스** — `:focus-visible` 포커스 링이 항상 보이고(3:1 대비), 오버레이가 닫히면 포커스가 트리거로 돌아간다.
- **역할·이름·상태** — 스크린리더가 역할(role), 이름, 상태(`aria-expanded`, `aria-checked` …)를 올바르게 읽는다.
- **색 대비** — 시맨틱 토큰 조합은 텍스트 4.5:1, UI 경계 3:1 이상이며 테스트로 검증된다.
- **사용자 설정** — 다크 모드, 동작 줄이기, Windows 고대비, 200% 확대에서 깨지지 않는다.
- **터치 타깃** — 모든 인터랙티브 컨트롤이 24×24px 이상이다.

## 사용하는 쪽에서 챙길 것

### 이름 붙이기

```tsx
// ✅ 아이콘만 있는 버튼은 aria-label
<IconButton aria-label="닫기"><XIcon /></IconButton>

// ✅ 입력에는 항상 보이는 레이블 — placeholder 는 레이블이 아니다
<Field.Root>
  <Field.Label>이메일</Field.Label>
  <Input placeholder="name@company.com" />
</Field.Root>
```

### 결과 알리기

로딩이 끝났거나 저장에 실패했다는 사실은 화면을 보지 못하는 사용자에게 **자동으로 전달되지 않는다.** [Toast](/components/toast/) 나 live region 으로 알린다.

### 오류 처리

- 오류는 [Field](/components/field/) 의 `invalid` + `Field.ErrorMessage` 로 컨트롤에 연결한다.
- 제출 시 오류가 있으면 **첫 번째 오류 필드로 포커스를 옮긴다.**
- 색만으로 오류를 표시하지 않는다 (ErrorMessage 는 아이콘을 함께 보여준다).

### 페이지 구조

- `<html lang="ko">` 지정
- 제목(`h1`~`h6`)을 순서대로 쓰고 건너뛰지 않는다.
- `<main>`, `<nav>`, `<header>` 랜드마크를 쓴다.
- 반복되는 내비게이션이 있으면 "본문 바로가기" 링크를 둔다 ([VisuallyHidden](/components/visually-hidden/) 의 `focusable`).

## 확인하는 방법

| 도구                               | 확인할 것                            |
| ---------------------------------- | ------------------------------------ |
| 키보드만 쓰기                      | Tab·Shift+Tab·Enter·Space·Esc·화살표 |
| VoiceOver (macOS `⌘ F5`)           | 이름·역할·상태가 자연스럽게 읽히는지 |
| NVDA (Windows, 무료)               | 위와 동일                            |
| 브라우저 200% 확대                 | 잘림·겹침 없음                       |
| macOS 동작 줄이기 / Windows 고대비 | 움직임 감소, 경계·포커스 보임        |
| axe DevTools 브라우저 확장         | 자동 검사                            |

<Aside type="tip">
  자동 검사(axe)가 잡는 문제는 전체 접근성 문제의 일부다. 키보드와 스크린리더로 **직접** 써보는 것을
  대신하지 못한다.
</Aside>
